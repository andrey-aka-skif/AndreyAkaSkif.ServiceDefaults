# Журнал изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Этот проект придерживается [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Журнал ведётся с версии 0.0.46. Заметки к более ранним выпускам —
в [Releases](https://github.com/andrey-aka-skif/AndreyAkaSkif.ServiceDefaults/releases).

## [0.0.48] - 2026-08-30

Выпуск переводит спецификацию на встроенную генерацию и разводит пакеты по ролям:
`.OpenApi` документ генерирует, `.Swagger` только показывает. Изменения ломающие —
потребителю потребуется поправить конфигурацию и вызовы.

### Изменено

- **Ломающее.** Спецификация генерируется встроенными средствами ASP.NET. Роли пакетов
  разведены: `.OpenApi` генерирует документ, `.Swagger` только показывает его в UI.
  Генератор Swashbuckle из библиотеки убран.
- **Ломающее.** Адрес спецификации при использовании `.Swagger` изменён с
  `/swagger/{ApiVersion}/swagger.json` на `/openapi/{DocumentName}.json`. Клиентам,
  которые генерируются по спецификации, адрес нужно поправить.
- **Ломающее.** Секция `SwaggerAppSettings` разделена на две: `OpenApi` описывает документ
  (`Title`, `Description`, `DocumentName`, `Version`, `Servers`), `Swagger` — показ
  (`Url`, `Name`).
- **Ломающее.** `ApiVersion` стал `OpenApi:Version` и означает версию контракта API —
  произвольную строку, а не `System.Version`: прежняя проверка отвергала любое значение
  с предрелизным суффиксом. Имя документа от версии отвязано и задаётся `DocumentName`,
  поэтому адрес спецификации при выпусках больше не меняется.
- **Ломающее.** Методы `.Swagger` заменены одной парой `AddSwaggerUi` / `UseSwaggerUi`:
  прежние `AddDefaultOpenApiViaSwagger` / `UseDefaultOpenApiViaSwagger` и
  `AddConfiguredOpenApiViaSwagger` / `UseConfiguredOpenApiViaSwagger` удалены. Деление на
  «по умолчанию» и «из конфигурации» потеряло смысл: обязательных ключей у секции нет.
- **Ломающее.** Описание конечной точки `/health` переехало в `.OpenApi`:
  `AddHealthCheckEndpointSwagger` и `AddHealthCheckEndpointWithSwagger` заменены на
  `AddHealthCheckEndpointDescription`, публичный тип `HealthChecksDocumentFilter` удалён.
  Сервисы проверки по-прежнему включает `AddHealthCheckEndpoint` из базового пакета.
- **Ломающее.** У `.Swagger` осталась единственная зависимость —
  `Swashbuckle.AspNetCore.SwaggerUI`. Ссылки на базовый пакет у него больше нет: кто
  получал `AndreyAkaSkif.ServiceDefaults` транзитивно, должен добавить его явно.
- **Ломающее.** `Swashbuckle.AspNetCore.Annotations` не поставляется: `[SwaggerOperation]`
  и `EnableAnnotations()` не работают. Описания операций задаются средствами фреймворка —
  `[EndpointSummary]`, `[EndpointDescription]`, `.WithSummary()`.
- **Ломающее.** Имена схем строит встроенный генератор, и для обобщённых типов они
  отличаются от прежних: клиенты по спецификации перегенерируются.
- На `net10.0` схема перечисления состоит из одного списка `enum`, без явного
  `type: string`: тип следует из значений — так документ пишет встроенный генератор
  в OpenAPI 3.1. Состав значений прежний.
- Доступность документа и показ UI управляются ключами `OpenApi:Visibility` и
  `Swagger:Visibility` с тремя значениями: `ByEnvironment` (умолчание), `Always`, `Never`.
  Прежде и документ, и UI существовали только в Development; теперь они доступны в любой
  среде, кроме Production, а в Production включаются ключом. Ключи независимы: в Production
  включать нужно оба.
- `Description` документа стал необязательным.

### Добавлено

- `.OpenApi`: пара `AddConfiguredOpenApi` / `UseConfiguredOpenApi` — атрибуция документа
  из секции `OpenApi`, и `AddHealthCheckEndpointDescription` — описание конечной точки
  проверки жизнеспособности с адресом-параметром
- в примере сервиса спецификация собирается в файл при сборке проекта
  (`Microsoft.Extensions.ApiDescription.Server`) и коммитится в репозиторий; CI сверяет
  собранную с зафиксированной

## [0.0.47] - 2026-08-30

Технический выпуск. Для потребителя пакетов изменений нет: публичный API, целевые
фреймворки и зависимости самих пакетов прежние.

### Изменено

- `Microsoft.NET.Test.Sdk` обновлён с 18.8.1 до 18.9.0 — зависимость тестового проекта,
  в поставку пакетов она не входит
- адрес реестра Gitea в воркфлоу публикации вынесен в переменные репозитория

## [0.0.46] - 2026-08-13

Технический выпуск. Публичный API и целевые фреймворки не менялись; из
изменений, доходящих до потребителя пакетов, — только патч одной зависимости.

### Изменено

- `Microsoft.Extensions.Hosting.Abstractions` обновлён с 10.0.10 до 10.0.11 —
  зависимость пакета `AndreyAkaSkif.ServiceDefaults.PostgreSQL`, остальных
  пакетов обновление не касается
- воркфлоу приведены к общему стандарту CI/CD: публикация переименована в
  `publish.yml` и переведена на встроенный `GITHUB_TOKEN`, разбор релизного тега
  вынесен в общий композитный экшен `.ci/actions/prepare-nuget-release`
- в CI добавлены проверка упаковки (`dotnet pack`) и сборка документации

### Добавлено

- зеркальный набор воркфлоу для внутреннего инстанса Gitea (`.gitea/workflows`)
- `CONTRIBUTING.md`: устройство репозитория, порядок выпуска, токены обоих
  реестров
